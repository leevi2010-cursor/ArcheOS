# ArcheOS 开发计划

## M0 基础规范

目标：建立信息生命周期、目录规则和 Agent 治理协议。

交付：
- `AGENTS.md`
- 目录结构
- 文档规范
- Issue → Plan → 实现 → 测试 → PR 的执行协议

## M1 通用信息处理 Pipeline（当前）

目标：跑通第一条通用信息消化链，不绑定销售、品牌、项目等具体业务场景。

第一版输入：
- 本地音频（会议、通话、工作讨论、头脑风暴等）

流程：

录音 → 转写 → 上下文保留（会议纪要） → 原子信息 → 残渣 → 人工审核

要求：
- 原始输入不可修改；
- 原子信息必须可追溯到来源证据；
- 不能安全吸收的信息不得静默丢弃，必须进入残渣；
- M1 停止在人工审核边界，不自动更新核心对象；
- 销售、品牌、项目等专门分析不属于 M1 Core，应由后续 Domain Agent 承担。

当前实现权威：GitHub Issue #4。

## M2 核心对象能力

支持：
- Person
- Company
- Project
- Event

具体吸收与更新规则需在进入 M2 前由架构决策和对应 Issue 明确。

## M3 决策闭环

支持：
- Goal
- Decision
- Action
- Feedback

具体模型需在进入 M3 前确认。

## M4 多格式输入

扩展候选：
- PDF
- 图片
- 视频
- PPT

原则：先验证通用信息消化闭环，再扩展输入格式和领域能力。
