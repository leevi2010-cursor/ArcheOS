# ArcheOS 产品说明

## 1. 产品定义

ArcheOS 是一个开放信息系统，用于把混乱、异构的信息输入逐步转化为可追溯、可复用的结构化信息，并支持后续基于目标进行判断、决策与反馈。

ArcheOS 的核心不是某一种业务应用，也不是单纯的文件管理或知识库，而是一条统一的信息生命周期：

**Input → Processing → Atomic Information → Structured Object → Decision → Feedback**

## 2. 用户价值

ArcheOS 帮助个人或组织：

- 保留原始信息与关键上下文；
- 把分散讨论、文件和事件转化为可复用的信息单元；
- 把多次来源的信息逐步聚合到人物、公司、项目等长期对象；
- 让结构化信息能够参与后续判断与决策；
- 保留来源、历史和不确定性，而不是只保存最终结论。

## 3. 产品边界

ArcheOS Core 不绑定销售、品牌、项目管理等具体业务场景。

销售分析、品牌定位分析、项目复盘等属于未来的 Domain Agent。它们建立在同一套 Core 信息处理能力之上，而不是各自重新实现一套信息生命周期。

## 4. 当前最小验证闭环

第一阶段使用音频作为最小输入，但输入内容可以是会议、通话、工作讨论、头脑风暴等任意业务领域的信息。

当前 M1 流程：

**音频 → 转写 → 上下文保留（会议纪要） → 原子信息候选 + 残渣 → 人工审核**

其中：

- 转写用于保存原始内容；
- 会议纪要用于保存整体上下文；
- 原子信息用于形成可独立审查、可追溯的信息候选；
- 残渣用于保存当前无法安全吸收的信息，并作为信息处理能力的健康反馈；
- 人工审核是 M1 的终点，不自动修改长期核心对象。

## 5. 后续演化方向

验证通用信息消化后，再依次解决：

1. 人工确认与对象吸收；
2. 领域专用解释（Domain Agent）；
3. 决策与反馈闭环；
4. PDF、图片、PPT、视频等多格式输入。

具体阶段顺序以 `docs/development/ROADMAP.md` 为准，当前开发任务以对应 GitHub Issue 为准。
